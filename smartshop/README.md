# SmartShop — Multi-Tenant SaaS Shop & Inventory Management System

SmartShop is a Django-based SaaS platform where multiple independent shop
owners manage their own inventory, sales, customers, suppliers, and
expenses under one platform, with a Super Admin overseeing approvals and
subscriptions.

## ⚠️ Honesty note about this build

This project was generated by an AI assistant (Claude) **without the
ability to install Django or run a real PostgreSQL database during
development** (no internet access in the build sandbox). Every file was
written carefully and all Python files pass a syntax check, but the app
was **not executed end-to-end** against a live database before delivery.
Please treat this as a strong, structured first version — run it locally,
work through the checklist below, and expect to fix a handful of small
issues (an odd import, a template tag) as you go, the way you would with
any large codebase you're integrating for the first time.

### What's fully implemented
- Multi-tenant architecture: Super Admin / Shop Owner / Staff (Cashier,
  Store Keeper, Manager) with centralized permission checks
- Registration → Email OTP verification → Super Admin approval/rejection
  (with reason) → resubmission workflow
- Login with email+password → second-factor Email OTP → session
- Session idle timeout + suspended/rejected/suspended-shop enforcement
- Products, Categories, Stock (stock-in, adjustment, full movement
  history)
- Sales / POS with atomic stock-deduction transactions (no overselling)
- Customers with credit/debt tracking and payments
- Suppliers + Purchases that restock inventory automatically (Premium)
- Expenses
- Dashboards (Super Admin platform-wide, Shop Owner per-shop) with
  Chart.js
- Subscription architecture: Plan / Feature / Subscription with a
  centralized `has_feature(shop, code)` check — no scattered
  `if plan == "premium"` — Free vs Premium enforced at the view level
- Reports: sales, stock, and a Premium profit/best-sellers report, with
  CSV export (free) and Excel/PDF export (Premium, via openpyxl/reportlab)
- Audit log for key actions (login, approvals, sales, stock changes)
- Responsive Bootstrap 5 UI with collapsible sidebar (hamburger on mobile)
- Basic English/Swahili i18n scaffold (`{% trans %}` tags + a starter
  `.po` file for common navigation/auth strings)
- Starter test suite: OTP correctness/expiry/reuse, atomic sale/stock
  transaction, tenant isolation (Shop A cannot touch Shop B's data)

### What's intentionally lighter than the original spec (v2 candidates)
- **i18n**: only core navigation/auth strings are translated in the `.po`
  file — most in-page text still needs translating, and you must run
  `compilemessages` locally (see below).
- **Test suite**: covers the highest-risk areas (auth, transactions,
  tenant isolation) but not every scenario in a full QA pass.
- **Notifications**: in-app `Notification` model + emails exist, but
  there's no automatic "low stock" or "subscription expiring" background
  job yet — that needs a scheduler (Celery/cron), which was deliberately
  left out per the spec's "don't overengineer" instruction.
- **Payments**: the Premium upgrade button flips the subscription
  immediately — there is no real payment gateway wired in (the spec asked
  for the architecture to support this later, not to implement billing
  now).
- Accessibility, exhaustive error-state polish, and full audit coverage
  of every model change are basic, not exhaustive.

## 1. Requirements

- Python 3.11+
- PostgreSQL 14+
- (Optional) `gettext` installed on your OS, if you want to compile the
  Swahili translations (`brew install gettext` / `apt install gettext`)

## 2. Setup

```bash
cd smartshop
python -m venv venv
source venv/bin/activate        # venv\Scripts\activate on Windows

pip install -r requirements.txt

cp .env.example .env
# edit .env: set SECRET_KEY, DATABASE_*, EMAIL_* (or leave EMAIL_BACKEND
# unset while DEBUG=True — OTP codes will print to your terminal instead
# of sending real emails, which is the easiest way to test locally)
```

### 3. Create the PostgreSQL database

```bash
createdb smartshop
# or from psql:
# CREATE DATABASE smartshop;
```

### 4. Migrate and seed

```bash
python manage.py makemigrations accounts shops subscriptions inventory sales customers suppliers expenses reports notifications audit
python manage.py migrate

# Creates Free/Premium plans, feature flags, and your first Super Admin:
python manage.py seed_smartshop --admin-email you@example.com --admin-password "ChangeMe123!"
```

### 5. (Optional) Compile Swahili translations

```bash
django-admin compilemessages
```

### 6. Run

```bash
python manage.py runserver
```

Visit `http://127.0.0.1:8000/accounts/login/` and log in with the Super
Admin credentials you seeded. From there:

1. Register a test shop at `/accounts/register/` (use a second browser
   or incognito window since you're logged in as Super Admin already).
2. Verify the email OTP — **if `EMAIL_BACKEND` is unset in DEBUG mode,
   the OTP code prints straight to your `runserver` terminal.**
3. As Super Admin, go to **Pending Applications** and approve the shop.
4. Log in as the shop owner, verify the login OTP, and you're in the
   dashboard — add products, make a sale on the POS screen, add a
   customer, etc.

## 8. Security notes

- Passwords are hashed via Django's built-in `PBKDF2` hasher — never
  stored in plaintext.
- OTP codes are hashed (`SHA-256`) before being stored; only the
  plaintext code sent by email is ever seen, and it's never logged.
- Every shop-scoped queryset filters by `request.user.shop` (from the
  authenticated session) — **never** by a shop ID taken from the URL or
  POST body, which is what prevents one shop from reading another's data
  (see `apps/core/permissions.get_request_shop`).
- `DEBUG=False` + real `SECRET_KEY` + `SESSION_COOKIE_SECURE=True` should
  all be set before any real deployment.

2. Add a scheduled job (Celery beat or a cron + management command) for
